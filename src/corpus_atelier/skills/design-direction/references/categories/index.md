# Deliverable categories

Category comes before style. Classify the deliverable first, decide what that kind of artifact must
get right, and only then describe the visual language in words. No style or movement catalog is
supplied, so a label can never stand in for a decision.

## Routing table

|---|---|---|

## Loading policy

Read only what the task needs:

- always use this routing table;
- open the one category that matches the deliverable, or two only for a genuine hybrid;
- never load several category files as a bundle.

If the brief does not determine a category, choose the closest one, state the choice in
`asset_category`, and keep the design decisions defensible for that artifact type.
