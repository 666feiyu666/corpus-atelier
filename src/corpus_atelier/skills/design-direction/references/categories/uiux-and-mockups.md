# UI and mockups

Adapted from the ui-ux-mockups slice of the GPT-Image2-Skill reference gallery
(https://github.com/wuyoscar/GPT-Image2-Skill, MIT). Condensed and rewritten for this pipeline.

## Decide before rendering

- The product fiction: an original name, category, and one-sentence purpose.
- The canvas: phone screen, desktop window, or component board, with its exact dimensions.
- The information architecture: header, key module, secondary rows, navigation.
- Real copy and plausible values: balances, percentages, dates, labels, button names.
- One platform convention; do not mix iOS, Android, and web idioms.

## Structure that carries the message

- Lay out header, content modules, and navigation in a consistent spacing scale.
- Use one accent color for primary action and state, not everywhere.
- Keep corner radii, icon weight, and type scale uniform.
- Put realistic data in charts and rows; empty placeholders read as unfinished.
- Keep contrast sufficient for text on cards.

## Common failures

- Lorem ipsum or placeholder bars instead of real copy.
- Inconsistent radii, icon styles, or spacing.
- Impossible charts, mismatched legends, or values that do not add up.
- Real brand logos or copied interface chrome.
- Generic adjectives replacing concrete modules.

## Visual QA

- Read every string; check truncation and ellipsis.
- Check alignment of cards, rows, and the spacing rhythm.
- Verify tap-target size and text contrast.
- Confirm numbers agree between summary and detail.
- Confirm no real brand mark and no unapproved text.

## Style vocabulary

None is supplied here. This guide sets what this kind of artifact must get right, not how it looks.
Choose the visual language in the observable dimensions of the style space, and state each choice as
the decision that produces it rather than as a label.
