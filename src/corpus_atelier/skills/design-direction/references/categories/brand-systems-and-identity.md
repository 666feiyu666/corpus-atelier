# Brand systems and identity

Adapted from the brand-systems-and-identity slice of the GPT-Image2-Skill reference gallery
(https://github.com/wuyoscar/GPT-Image2-Skill, MIT). Condensed and rewritten for this pipeline.

## Decide before rendering

- What is being designed: a single mark, a wordmark, or an identity system board.
- The exact name and any approved descriptor; a raster mark is not editable vector artwork.
- Primary palette, one accent, and the type pairing.
- One or two real application surfaces: card, packaging, social post, signage.

## Structure that carries the message

- Build the board in zones: mark, wordmark, palette chips, type specimen, touchpoints.
- Keep one grid and one optical center per zone; generous white space protects the mark.
- Show the mark at a small size as well as a large one.
- Keep the accent color purposeful: one recurring use, not scattered decoration.
- If the brand owns a packaging system, keep the same geometry across variants.

## Common failures

- A generic swoosh, globe, or gradient standing in for an identity.
- A mark that collapses when scaled down or reproduced in one color.
- Every application rendered at once, leaving none convincing.
- Mockups with wrong perspective or impossible material behavior.
- Invented legal lines, registration marks, or partner logos.

## Visual QA

- Spell the brand name and descriptor exactly.
- Reduce the mark to thumbnail and to one color; check it still reads.
- Count colors: the stated palette, no accidental extras.
- Check alignment of the zone grid and the legibility of the type specimen.

## Style vocabulary

None is supplied here. This guide sets what this kind of artifact must get right, not how it looks.
Choose the visual language in the observable dimensions of the style space, and state each choice as
the decision that produces it rather than as a label.
